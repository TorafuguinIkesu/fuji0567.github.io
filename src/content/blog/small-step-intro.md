## はじめに：保育現場のリアルな課題

保育園や幼稚園の現場では、先生方が日々子どもたちの見守りや安全管理に追われています。その中で大きな課題となっているのが**日々の記録・連絡業務の負荷**です。

- **成長の瞬間が記録に残らない**：先生が両手を使って保育をしている最中、子どもの「小さな成長（過程）」を見つけてもメモを取る余裕がない。
- **親子の会話のきっかけ不足**：連絡帳には「今日も元気に過ごしました」といった定型句になりがちで、家庭での具体的な会話の糸口になりにくい。
- **怪我の記録の曖昧さによる法的・信頼リスク**：「いつ・どこで・どのように怪我をしたか」の記録が曖昧になり、保護者との信頼関係に影響する。

**SMALL STEP**は、これらの課題をハードウェアとエッジAIの力で解決するために開発された保育園支援システムです。

---

## SMALL STEP がもたらす3つの価値

### 1. 「過程（小さな一歩）」を褒める対話を生む
心理学の研究（Mueller & Dweck, 1998）において、結果（知能そのもの）よりも「過程や工夫・努力」に焦点を当てて褒めることが子どもの意欲を高めると示されています。
SMALL STEP は園内での子どもの発言や挑戦の文脈を記録し、保護者へ「今日、○○ちゃんが『みてみて！』と鉄棒に挑戦していました」といった具体的な親子の会話の種を届けます。

### 2. ハンズフリー＆ワンタップで保育士の負担ゼロへ
先生はクリップ型の超軽量ウェアラブルマイクをエプロンに装着するだけ。保育中にスマホやメモ帳を開く必要はありません。夕方にAIがまとめた記録をアプリ上でワンタップ承認するだけで、連絡が完了します。

### 3. 生データを外に出さないプライバシー保護設計
園内の会話音声をそのまま外部のクラウドへ送信することは、プライバシー上の大きなリスクです。SMALL STEP は園内設置のエッジサーバー内で話者分離・テキスト化・匿名化を完結させ、外部クラウドへは個人特定不可能なデータのみを渡します。

## システムの全体像と技術構成

市販の小型モジュールと最新のAIモデルを巧みに組み合わせ、堅牢でプライバシーに配慮したアーキテクチャを実現しています。

| レイヤー | 採用技術 | 役割・特徴 |
| :--- | :--- | :--- |
| **デバイス層** | ESP32 / INMP441 (MEMSマイク) | クリップ型・軽量・省電力。Wi-Fi経由で園内エッジ機へ音声送信 |
| **エッジ処理層** | pyannote.audio / OpenAI Whisper / ローカルLLM (Llama 3 / Qwen 2.5) | 園内サーバーで話者分離・文字起こし・怪我と成長の分類・匿名化を実行 |
| **クラウド層** | Claude / Supabase | 匿名化データから高品質な「会話の種」を生成。怪我の緊急度再判定 |
| **アプリ層** | Flutter (iOS / Android) | 先生がワンタップで内容を確認・承認・修正するための直感的なUI |
| **配信層** | LINE Messaging API | 保護者が普段から使うLINEへ直接配信。専用アプリ導入の手間を解消 |

## 従来のソリューションとの違い

| 項目 | 一般的な連絡帳アプリ | 見守りカメラ | SMALL STEP |
| :--- | :---: | :---: | :---: |
| **記録の自動化** | ✕ (手動入力) | ◯ (映像のみ) | **◯ (音声から文脈を抽出)** |
| **会話のきっかけ創出** | ✕ | ✕ | **◯ (子どもの言葉を引用)** |
| **即時の怪我通知** | ✕ | ✕ | **◯ (二段判定で即時配信)** |
| **先生の入力負担** | 重い | 軽い | **極小 (ワンタップ承認のみ)** |
| **プライバシー (園内完結)**| クラウド保存 | 映像流出リスク | **◯ (エッジ処理・生データ破棄)** |

## おわりに

SMALL STEP は、先生を日々の記録業務から解放して子どもと向き合う時間を取り戻し、保護者には我が子の「かけがえのない過程」を届けます。
